## 二、v3.5.0 已完成整改

### 2.1 审批机制（P0）

- **重放窗口关闭**：回放凭证由审批单 ID 改为一次性随机 `exec_key`（仅 approve 流程内存持有、不回传客户端），状态机 `approved → executing → executed/denied`，`exec_key` 执行后立即清除。伪造旧式头（以 aid 为凭证）经实测无效。
- **职责分离**：审批人不能审批自己提交的申请（403）。
- **admin 免审批可配置**：新增 `approval_admin_bypass`，**默认关闭**——开启审批模式后 admin 执行高危操作同样需审批；需要时可在系统设置中打开。

### 2.2 认证与密钥（P0）

- 密码哈希：SHA-256+8 字节盐 → **scrypt（N=2^14, r=8, p=1）+ 16 字节随机盐**；存量旧格式哈希在登录校验通过后自动升级。
- 默认管理员首次登录强制修改密码（`must_change_password` 标记，前端强制弹窗）。
- 用户接口不再回显 pwd/salt 字段。

### 2.3 敏感信息（P0）

- 机器人通道 webhook/token/secret 对外一律掩码（`https:******7890` 形式），明文仅存库。
- 终端/WebShell/通知的异常细节改为服务端留痕，客户端仅返回通用提示。

### 2.4 Agent 工具调用循环（P1）

- 新增 `POST /api/ai/agent`：Claude **function calling**（tools 协议）驱动平台真实工具：`nmap_scan`（真实扫描引擎）、`list_assets`、`get_scan`、`create_report`；循环至模型给出结论或达到迭代上限。
- 模拟模式（无 API Key）内置决策序列，**仍真实调用扫描引擎**，离线可演示。
- 前端新增「Agent 工具调用」面板：工具调用轨迹（终端风格）+ 分析结论 + Token 用量。
- 「多智能体编排」措辞修正为「多模式 AI 编排」（诚实表述，避免验收被追问）。
